## New

- **Clear Site Data for This Profile…** now works with the Chromium engine. It removes cookies, cache, local storage, IndexedDB and service workers for that profile only; history, passwords and site permissions stay. Clearing one site's data also works when no tab shows that site.

## Faster

- Library history search no longer blocks visit recording or sync: searching 200,000 visits for a common word takes 18.5 ms → 1.8 ms, and for a site name 62 ms → 0.8 ms.
- While the assistant writes, each new word costs 24 ms → 1.0 ms of main-thread time on a 30-message conversation (peaks 52–134 ms → 1.2 ms).
- Opening the assistant panel on a 120 Hz display draws 20 → 47 frames, with no frozen frames.

## Fixed

- Links opened with ⌘-click, ⌥-click into a split or ⇧-click into Peek now keep their originating page: sites see where the click came from, and their strict same-site cookies are no longer sent on cross-site opens.
- Browser-internal debug pages and `javascript:` addresses can no longer be loaded from session restore, AppleScript, link routing or other apps.
- AppleScript can no longer run JavaScript in a private window by setting a tab's URL to `javascript:`.
- Link routing rules now match only a link's site and path, so a rule cannot be triggered by text in the query string.
- Links opened from other apps have embedded user names and passwords removed.
- Removing a profile now also deletes its web cache and its cookie backups.
- Link previews refuse local-network and private addresses, including after redirects.
- Update checks no longer send cookies.
- Assistant animations, the Today sidebar accessory and palette transitions follow the display's refresh rate.

## Known limits

- Clearing one site's data does not remove that site's cookies from migration backups; they expire within 30 days.
- The context menu commands Open Link in New Tab and Open Link in Split View still drop the originating page.
- Going back manually to 0.74.0 leaves history unavailable (not deleted) until the next update.
