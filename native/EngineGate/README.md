# Native engine gate

This is an isolated diagnostic host for the pinned CEF 156 distribution. It is not the Orbit application and does not select its final engine.

`chrome-views` creates two Chrome-style browser views in separate hidden CEF windows. `chrome-profiles` creates the same hidden views with separately initialized request contexts and private synthetic cache paths. `chrome-workers` uses a shared context and delays the second document for at least 40 seconds after the first report to observe a new worker evaluation and persisted extension storage. `alloy-appkit` creates two hidden AppKit parents and asks for Chrome style, allowing the observed runtime to establish whether native parenting forces Alloy. None of these paths calls `Show` or activates NSApplication. Popups are rejected during this first runtime gate.

The host requires an absolute new synthetic artifact directory bearing the laboratory marker, a numeric loopback HTTP origin and `--use-mock-keychain`. A missing mock flag or an explicit disabled sandbox aborts before CEF initialization. Root/cache/log paths stay in the synthetic directory; the production applications, personal browser profiles and tracking origin 4318 are not used.

The MV3 fixture and HTTP runner report actual API results. A successful compilation, a requested runtime style or a native page load cannot count as extension compatibility. Hidden-window results cannot validate visible focus, IME, accessibility, popovers, Split View or Orbit visual fidelity. Store installation and updates remain separate gates from loading a lab extension.

The profile mode checks distinct context identity, first-read page `localStorage` and cookie isolation, server-observed synthetic cookies, and first-read `chrome.storage.local` isolation. `run --style chrome-profiles --restart` performs an initial run and a full host relaunch on the same newly created synthetic profiles and fixture origin. The restore phase requires each profile's page and extension storage to contain its own earlier marker before writing again. Both phases must pass independently and shut down completely. No existing artifact root or personal data can be selected.

`chrome-native-tabs` and `chrome-native-split` require `--native-visible`. They create one native Chrome window, then execute the corresponding Chrome command only after the first page's complete passing extension report and network controls. The runner atomically publishes a private readiness marker; it exposes no native command endpoint to pages. The second host navigates to synthetic page B. Both pages must pass the 19-result fixture with validated numeric tab/window/split metadata. The host requests unprivileged layout reports after both pages load, and the runner independently checks tab visibility or two visible split panes. Native-window closure is required in addition to both host callbacks. These modes may activate their synthetic window under the user's explicit visual-test authorization; the hidden modes retain strict invisibility/inactivity checks.

This host uses no page-to-native privileged bridge. Native event output is restricted to synthetic process/browser identity, status, requested options and observed runtime/visibility; extension results travel through the loopback HTTP fixture server.

`chrome-native-store --native-visible` extends the ordinary native-tab scenario with a bounded, coordinator-driven official Store installation in its fresh synthetic profile. Private one-shot empty control files request only the fixed uBOL listing, the internal extension manager, or early closure. The exact Google consent flow is allowed; no sign-in is performed. The runner requires an enabled Store runtime observation and matching installed internal-manifest evidence. Its lifetime/watchdog are 180/210 seconds. `--store-resume RUN_ID` permits one restart of that same private profile only after a clean successful installation and unchanged extension evidence. Initial reports and controls are preserved; restore results are separate. No arbitrary existing profile can be selected. See [the actual Store checkpoint](../../docs/native-port/chrome-store-2026-10-25.md) for proof and limits.
